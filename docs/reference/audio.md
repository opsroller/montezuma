# Audio

Facts about the game's sound: formats, levels and every file behind each
cue. The cue names themselves are the contract in
[contracts.md](contracts.md#audio-cues-owner-sound-designer-wp-15-to-17--proposed).
Why it sounds this way is in
[the sound direction](../explanation/sound-direction.md); how to rebuild
or add sounds is in
[the how-to](../how-to/regenerate-or-add-sounds.md).

## Sources and formats

| Category | Folder | Delivered as | Made by |
|---|---|---|---|
| Sound effects | `game/assets/audio/sfx/` | 48 kHz 16-bit mono WAV, imported by Godot with QOA compression (the Godot default), held in memory | `tools/audio/sfx_gen.py` |
| Music and ambience | `game/assets/audio/music/` | 48 kHz stereo Ogg Vorbis, quality 3 (about 100 kbit/s), streamed | `tools/audio/music_gen.py` |

All audio is generated by the scripts in `tools/audio/` from numpy
synthesis; there are no recordings, samples or presets. The scripts are
the source, so only the rendered delivery files are committed beside
them. `tools/audio/synth.py` holds the shared instruments.

## Levels

Measured to ITU-R BS.1770 with ffmpeg's `ebur128` meter. The project
profile names no loudness target, so the mobile-style target applies:
the full game mix aims at **-18 LUFS integrated ±2 LU, true peak at most
-1 dBTP**. Files are levelled by category relative to that, not
peak-normalised.

| Category | Meter | Target | Used for |
|---|---|---|---|
| frequent | loudest 400 ms momentary | -24 LUFS | swaps, landings, menu ticks: heard hundreds of times |
| feedback | loudest 400 ms momentary | -19 LUFS | matches, cascades, bonuses, totem charge |
| alert | loudest 400 ms momentary | -17 LUFS | quota done, time warning: must cut through music |
| stinger | loudest 400 ms momentary | -16 LUFS | level won or lost, trophy, totem fire |
| music | integrated | -22 LUFS | menu and episode loops: under gameplay sounds |
| ambience | integrated | -30 LUFS | the jungle bed under everything |

Every file is rendered with a true-peak ceiling of -1.5 dBTP (0.5 dB of
margin under the -1 dBTP limit). Where the ceiling binds, the file lands
a little under its category target (`steel_break`).

## Music and ambience

Measured values from `tools/audio/reports/music_loudness.json`. Every
piece is a seamless loop: it renders into a circular buffer, so note
tails and reverb wrap across the loop point, and the decoded length is
exact to the sample. Loop playback is set by the audio system, not by
import settings.

| Cue | Mood | BPM | Bars | Key and mode | Length (s) | Integrated (LUFS) | True peak (dBTP) | Size (MB) |
|---|---|---|---|---|---|---|---|---|
| `music_menu` | calm and open | 80 | 32 | D pentatonic with a major sixth | 96.0 | -22.0 | -11.6 | 1.02 |
| `music_play_1` | curious, a gentle pulse | 92 | 32 | D minor pentatonic | 83.5 | -22.0 | -11.5 | 1.05 |
| `music_play_2` | shadowed, a darker mode | 96 | 32 | E Phrygian | 80.0 | -22.0 | -10.7 | 1.01 |
| `music_play_3` | steady, more drive | 100 | 32 | A minor pentatonic | 76.8 | -22.0 | -9.6 | 0.98 |
| `music_play_4` | bright and busy | 104 | 32 | C pentatonic with a major sixth | 73.8 | -21.9 | -10.9 | 1.06 |
| `music_play_5` | urgent, the finale | 110 | 32 | B pentatonic with a flat second and major third | 69.8 | -22.0 | -10.9 | 1.02 |
| `ambience_jungle` | humid jungle, birds and insects | — | — | — | 64.0 | -30.2 | -14.7 | 0.84 |

Each piece is 4/4. Bars 1-16 and 17-32 carry two different tunes over
the same groove, with a two-bar drum break at bar 17. Intensity rises
by episode: the menu has no hide drum; episodes 1 to 5 add the hide
drum, then busier bass, rattle and bell layers.

Transitions: a music cue cross-fades from the current piece over the
audio system's `music_fade` (1.5 s by default), at any moment; ambience
cross-fades the same way on its own player. There are no stingers
quantised to the beat: the effect stingers (level won, trophy) duck the
music instead.

Total: 6.9 MB, inside the web demo's 40 MB budget even with every
piece included; the demo needs only `music_menu`, `music_play_1` and the
ambience.

## Audio system

`GameAudio` (C++, `extension/src/audio/`) is the only way game code makes
sound. It runs as the autoload `GameAudio` (`game/scenes/audio/game_audio.tscn`,
process mode Always so menus sound while the game is paused). C++ code
calls `GameAudio::get_singleton()->play("match")`; scenes and UI call
`GameAudio.play("ui_click")` on `/root/GameAudio`.

### Methods

| Method | Does |
|---|---|
| `play(name)` | Plays a cue. One-shots take a pooled voice; music and ambience cues cross-fade their loop player. Unknown names warn once and stay silent |
| `stop(name)` | Stops a cue's voices, or fades out its loop |
| `stop_music(fade_seconds)` | Fades the music out |
| `has_cue(name)`, `get_cue_names()` | Look up the table |
| `set_volume(bus, linear)`, `get_volume(bus)` | Player volume per bus, 0 to 1. The settings screen calls these and saves the values; never set those bus volumes on `AudioServer` directly, because ducking rewrites them |
| `set_muted(bus, muted)`, `is_muted(bus)` | Mute per bus |
| `get_active_voice_count()` | Voices playing now |
| `quit(exit_code = 0)` | Stops every sound and quits the game once Godot has freed them (see [Quitting](#quitting)). Use it instead of `SceneTree.quit()` |

Properties: `cue_table_path` (default `res://assets/audio/cues.json`),
`music_fade` (default 1.5 s).

### Buses

Created at startup when missing, all sending to `Master`:

| Bus | Carries |
|---|---|
| `Master` | Everything; a hard limiter at -1 dB ceiling as a safety net |
| `Music` | `music_*` cues |
| `Ambience` | `ambience_*` cues |
| `SFX` | Gameplay one-shots |
| `UI` | `ui_*` cues |

### Cue table

`game/assets/audio/cues.json`: `{"cues": {name: entry}}`, file paths
relative to `game/assets/audio/`.

| Field | Default | Meaning |
|---|---|---|
| `files` | required | Variations; picked at random, never the same one twice in a row |
| `type` | `one_shot` | `one_shot`, `music` or `ambience`. Music and ambience must be Ogg Vorbis; they loop |
| `bus` | by type | `SFX` for one-shots, `Music`, `Ambience` |
| `volume_db` | 0 | Offset on top of the file's level |
| `volume_random_db` | 0 | ± random volume per play |
| `pitch_random_semitones` | 0 | ± random pitch per play |
| `max_voices` | 4 | Instances of this cue at once; past it the oldest is cut |
| `priority` | 2 | 1 critical, 2 feedback, 3 flavour |
| `duck_music` | priority is 1 | Duck music and ambience while it plays |

Every file the table names must load: a missing one is an error at
startup, which the headless CI run catches.

### Voices, priority and ducking

- 24 one-shot voices in all. When every voice is busy, a new cue takes
  the voice of the least important, oldest sound that is no more
  important than itself; if there is none, the new cue is dropped.
- A priority-1 cue ducks `Music` and `Ambience` by 4 dB, attacking at
  40 dB/s, holding 0.6 s, releasing at 8 dB/s.
- Nothing is allocated per frame: voices and loop players are created
  once in `_ready`.

### When each cue plays

The game scene (WP-28) calls these; the board view calls the board ones
on the animation frame they belong to.

| Cue | Event |
|---|---|
| `swap` | A legal swap starts animating |
| `swap_illegal` | An illegal swap bounces back (`play_illegal`) |
| `match`, `cascade_<n>` | Each cascade step's clear: step 0 plays `match`, step *n* plays `cascade_<n>` (8 and above play `cascade_8`) |
| `piece_land` | Falling pieces settle, once per step, not per piece |
| `gem_collect` | A gem piece is cleared |
| `steel_break`, `chain_break` | A steel piece is destroyed; chains on a cell break |
| `bonus_earned` | A power-up appears on the board (a 4+ match places one) |
| `bonus_use_<id>` | A power-up goes off when its piece is cleared |
| `totem_charge` | A totem gains charge without firing; at most once per move |
| `totem_fire_<id>` | A totem fires |
| `quota_done` | A colour quota is met (levels with quotas) |
| `time_warning` | Time left crosses the warning threshold |
| `level_won`, `level_lost` | `level_finished` |
| `trophy` | A trophy unlocks |
| `ui_click`, `ui_back` | Button press; back or cancel |
| `music_menu` | Title and map screens |
| `music_play_<episode>` | A level starts in that episode |
| `ambience_jungle` | Under every level |

### Self-test

`godot --headless --path game --quit-after 120 -- --audio-selftest`
plays every cue once, checks the voice limit and a missing cue, and
prints `GameAudio self-test: <n> cues, 0 failures`. CI runs it in the
Linux extension job and fails on any other line.

### Quitting

Godot 4.7 frees a stopped sound only after two more audio mix steps and
one more frame. Quitting while a sound plays (Godot's `--quit-after`,
`SceneTree.quit()`, or the window closing with no handler) tears the
tree down before that, so the sound's stream outlives the engine and
Godot prints `ERROR: <n> resources still in use at exit` and a leaked
ObjectDB warning. Every level plays music and ambience, so any quit from
a level hits this.

`GameAudio` therefore owns quitting:

- `quit(exit_code)` stops every voice and loop at once, ignores later
  `play()` calls, and quits once the audio server has dropped every
  stopped playback, or after 500 ms.
- It turns off `SceneTree.auto_accept_quit`, so closing the window calls
  `quit(0)`.
- The UI's `quit` action calls it.
- The `--quit-after-frames=<n>` user argument calls it after `<n>`
  frames. CI's in-level run and screenshot captures use it; keep Godot's
  `--quit-after` only as a larger safety net against a hang.
